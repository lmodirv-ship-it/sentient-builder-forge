# خطة تطوير نواة وتشغيلها على خادم VPS 66

الهدف: يصبح الخادم `213.156.132.166` مقر المحرك والتخزين والإنشاء، وتبقى هذه الواجهة للعرض فقط، ويفتحها تطبيق الهاتف. مع توحيد العقول الأربعة الموجودة في نواة خلف وكيل مركزي واحد.

## 0) الإجابة على سؤالك

نعم: Ollama هو النموذج الذي يفكّر ويولّد النص. الوكيل (Agent) هو العقل المدبّر الذي يقرر: هل هذا سؤال ذاكرة أم أداة أم مهمة برمجة، وأي نموذج يُستدعى، وأي أداة تُنفّذ، وماذا يُحفظ بعد ذلك. النموذج ينتج كلامًا، والوكيل ينتج قرارًا.

## 1) توزيع الأدوار

```text
الهاتف (Capacitor)  ──▶  الواجهة الحالية (عرض فقط)  ──▶  خادم VPS 66
                                                        ├─ الوكيل المركزي
                                                        ├─ سجل الأدوات
                                                        ├─ الذاكرة والبحث الدلالي
                                                        ├─ قاعدة بيانات PostgreSQL
                                                        ├─ تخزين الملفات والنتائج
                                                        ├─ طابور مهام الإنشاء
                                                        └─ عقد النماذج (Ollama) وخدمات HN
```

- الواجهة لا تنشئ ولا تخزن شيئًا: ترسل الطلب، تتابع حالته، تعرض النتيجة.
- تطبيق الهاتف يفتح `https://chat.hn-chat.com` نفسه (نفس الحساب ونفس النتائج).

## 2) الوكيل المركزي — توحيد العقول الأربعة

اليوم منطق التوجيه موزّع بين الصفحة الرئيسية وسجل الأدوات ومحرك المهام والـ Builder. ننقله كله إلى وكيل واحد على الخادم:

```text
طلب المستخدم
   ↓
الوكيل المركزي
   ├─ طبقة القوالب (جواب فوري من جدول القوالب)
   ├─ عقل الذاكرة        → بحث هجين + دلالي + إعادة ترتيب
   ├─ محرّك الأدوات      → سجل أدوات موحّد ومنفّذ واحد
   ├─ محرّك المهام/الكود → مهمة لها حالة ونتيجة
   └─ محرّك البناء       → توليد تطبيق ومعاينة وتصدير
   ↓
اختيار النموذج من عقد Ollama (نفس العائلة أو بديل أصغر عند الغياب)
   ↓
النتيجة + حفظ الحوار الناجح في الذاكرة
```

كل مسار يصبح نقطة واحدة واضحة بدل منطق متناثر داخل صفحة الواجهة.

## 3) طبقة تشغيل موحّدة (Windows / Linux)

المشروع اليوم يخلط بين مسارات Windows وأوامر Linux. نضيف طبقة واحدة:

```text
الوكيل → طبقة التشغيل → (Windows)  أو  (Linux/VPS)
```

- الوكيل يطلب «اقرأ ملف» أو «أعد تشغيل موقع» دون معرفة نظام التشغيل.
- كل أداة تُعرّف بالبرنامج ومعاملاته المسموحة، وتُنفَّذ بـ spawn بدون shell بدل تمرير نص كامل.
- الوظائف الحالية تبقى كما هي؛ تُستدعى من خلف الطبقة الجديدة ولا يُحذف منها شيء.

## 4) ما يُركَّب على الخادم

| المكوّن | الدور |
|---|---|
| Nginx + شهادة HTTPS | بوابة الدخول على نطاق فرعي `api.hn-chat.com` |
| خدمة المحرك (Node) | الوكيل المركزي ونقاط العقد في القسم 5 |
| PostgreSQL | القوالب، المستخدمون والأدوار، المهام، السجلات، الإعدادات، الذاكرة |
| مجلد التخزين | ملفات النتائج مع روابط تحميل موقّعة |
| طابور المهام | كل إنشاء وظيفة لها حالة: بانتظار، جارٍ، منتهٍ، فشل |
| مدير العمليات | إعادة تشغيل تلقائية وسجلات يومية |

## 5) العقد بين الواجهة والخادم

- `POST /v1/ask` — سؤال النواة: جواب فوري من القوالب إن تطابق، وإلا يدخل مسار الوكيل.
- `POST /v1/jobs` — طلب إنشاء (صورة/صوت/فيديو/موقع/سيرة/تحليل صورة) يرجع رقم المهمة.
- `GET /v1/jobs/:id` — حالة المهمة ونتيجتها ورابط ملفها.
- `GET /v1/tools` و`POST /v1/tools/:id/run` — سجل الأدوات وتنفيذها عبر الطبقة الموحّدة.
- `GET /v1/templates` و`PUT /v1/templates/:code` — قراءة وتعديل القوالب من لوحة التحكم.
- `GET /v1/admin/*` — بيانات لوحة التحكم (نظرة عامة، مستخدمون، خدمات، سجلات).

## 6) نقل البيانات

1. تصدير الجداول الحالية كاملة: `templates` (111 قالبًا بمعرفاتها S00001…)، الأدوار، الإعدادات، الخدمات، السجلات، المهام.
2. إنشاء نفس البنية على قاعدة الخادم.
3. استيراد البيانات والتحقق من تطابق العدد سطرًا بسطر.
4. لا يُحذف شيء من القاعدة الحالية — تبقى نسخة مرجعية.

## 7) تعديل الواجهة هنا

- استبدال نداءات الإنشاء الداخلية بنداءات إلى الخادم عبر عنوان واحد في الإعدادات.
- شاشة الدردشة: إرسال ← «جارٍ العمل» ← عرض النتيجة عند اكتمال المهمة، مع بث تدريجي للنص.
- لوحة التحكم وصفحة القوالب تقرأان وتكتبان على الخادم مباشرة.
- إبقاء الأزرار والتصميم كما هي دون أي تغيير شكلي.
